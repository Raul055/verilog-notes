# Signed Numbers Representations
There are various ways to represent a signed number in binary.
- **Sign-and-Magnitude**: the *MSB* represent the sign, while the rest represent the magnitude. For example, asuming `4-bits`, `1110` represents $(-6)_{10}$.
- **1's Complement**: the number is taken its 1's complement (AKA ~). For example, asuming `4-bits`, `1110` is complemented as `0001` and represents $(-1)_{10}$.
- **2's Complement**: the number is taken its 2's complement (AKA ~ and then +1). For example, asuming `4-bits`, `1110` is complemented as `0001`, then added `+1` so `0010` and represents $(-2)_{10}$.

Here, as we are dealing with `4-bit numbers`, the *carry-out* bit does not matter. At the same time, see that the first and fourth operations are outside the range of the `4-bits`, so we've encountered an **overflow**.

We can implement the `adder_substractor` module to deal with signed numbers using the `rca_nbit` module from [[2. Generic Verilog Code Parametrization]].

```verilog
module adder_substractor
	#(parameter N=4)
	(
		input [N-1:0] x, y,
		input add_n,
		output [N-1:0] s,
		output c_out,
		output overflow
	);
	
	// xor_y
	wire [N-1:0] xor_y;
	
	// generate xor gates
	generate
		genvar k;
		for(k = 0; k < N; k = k + 1)
		begin: bits
			assign xor_y[k] = y[k] ^ add_n;
		end
	endgenerate
	
	// rca
	rca_nbit #(.N(N)) A0 (
		.x(x),
		.y(y),
		.c_in(add_n),
		.s(s),
		.c_out(c_out)
	);
	
	// overflow flag
	assign overflow = (x[N-1] & xor_y[N-1] & ~s[N-1]) | (~x[N-1] & ~xor_y[N-1] & s[N-1]);
	
endmodule
```

The **overflow** flag is launched when:
> The *MSB* of `x` and `y` are `1` and `s` is `0` (*two negative numbers were added and the sum was positive*) **OR** the *MSB* of `x` and `y` are `0` and `s` is `1` (*two positive numbers were added and the sum was negative*).
