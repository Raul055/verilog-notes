Counters can be used as timers. For them, according to the frequency of the `clk`, we can determine the `FINAL_VALUE` a **modulus counter** shall reach in order to reach the desired period of our timer.

![[counter-timer.png | center]]

For example, supose a `clk` signal of $f=100MHz$ and the desired period of the counter is $T=2.56 \textmu s$, we can calculate the `FINAL_VALUE`.
$$ T = \frac{1}{f} = \frac{1}{100 MHz} = 10 ns$$
Given that the period of the `clk` is $10ns$, we can obtain the `FINAL_VALUE` that the counter shall reach.
$$ FINAL \textunderscore VALUE = \frac{T_{timer}}{T_{clk}} - 1=\frac{2.56 \textmu s}{10ns} - 1 = \frac{2560ns}{10ns} - 1 = 256 - 1 = 255$$
This module represent a timer with the obtained `FINAL_VALUE` as a *parameter*.
```verilog
module timer_parameter
	#(parameter FINAL_VALUE=255)
	(
		input clk,
		input reset_n,
		input enable,
		output done
	);
	
	localparam N = $clog2(FINAL_VALUE);
	reg [N-1:0] Q_reg, Q_next;
	
	// Register
	always @(posedge clk, negedge reset_n)
	begin
		// Asynchronous reset
		if(~reset_n)
			Q_reg <= 0;
		// Enable counter
		else if(enable)
			Q_reg <= Q_next;
		// Counter disabled, maintain current value
		else
			Q_reg <= Q_reg;
	end
	
	// Next state logic
	assign done = Q_reg == FINAL_VALUE;
	
	always @(*)
		Q_next = done? 'b0: Q_reg + 1;
	
endmodule
```

We can also implement  a timer that requires an input for a dynamically timer (not parametrized). The following is a `N-Bits` **Input Timer**.

```verilog
module timer_input
	#(parameter N=4)
	(
		input clk,
		input reset_n,
		input enable,
		input [N-1:0] FINAL_VALUE,
		output done
	);
	
	reg [N-1:0] Q_reg, Q_next;
	
	// Register
	always @(posedge clk, negedge reset_n)
	begin
		// Asynchronous reset
		if(~reset_n)
			Q_reg <= 0;
		// Enable counter
		else if(enable)
			Q_reg <= Q_next;
		// Counter disabled, maintain current value
		else
			Q_reg <= Q_reg;
	end
	
	// Next state logic
	assign done = Q_reg == FINAL_VALUE;
	
	always @(*)
		Q_next = done? 'b0: Q_reg + 1;
	
endmodule
```
