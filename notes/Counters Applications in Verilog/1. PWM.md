**PWM (Pulse Width Modulation)** is a way of controlling how much power a device gets by switching a digital pin rapidly between HIGH and LOW, instead of using a true analog voltage.

# Main Characteristics
## Duty Cycle
The **duty cycle** is the percentage of each cycle the signal spends HIGH.

![[duty-cycle-1.png | center]]

The *duty cycle* can be modified according to the percentage needed.

![[duty-cycle-2.png]]

We care about the *duty cycle* because of the **average voltage** the PWM generates. If we connect an analog device, the PWM signal will be read (according to the *duty cycle*) as the **average voltage** generated over time. The way we can compute the **average voltage** that can be read is borrowed the same way we can obtain *expectation* from probability. It follows the expression.
$$ E[X] = \textmu_{X} = \sum_{i} x_{i} P_(x_{i}) $$
where $x_{i}$ is each possible outcome and $P(x_{i})$ is its probability. From this expression, considering $V$ as voltage, we can define the *expected voltage* as:
$$ E[V] = \textmu_{V} = \sum_{i} v_{i}P(v_{i}) $$
The instant $t$ is uniformly distributed over $[0,T]$, so: 
$$f(t)=\frac{1}{T}$$
We know that $V$ can only take two values (this being a digital signal), which are $V = V_{cc}$ and $V = 0$. Also, $V=V_{cc}$ when $0 \leq t \leq t_{on}$, so:
$$ P(V_{cc}) = \frac{t_{on}}{t_{PWM}}$$
With the definition of *duty cycle*:
$$ P(V_{cc}) = \frac{t_{on}}{t_{PWM}} = d$$
So, because the sum of all probabilities is 1, we can obtain $P(0)$:
$$1 = P(V_{cc}) + P(0)$$
$$P(0) = 1 - P(V_{cc}) = 1 - d $$
Going back to the *expected voltage* expression:
$$ E[X] = \textmu_{X} = \sum_{i} x_{i} P_(x_{i})=0(P(0)) + V_{cc}(P(V_{cc})) $$
$$ E[X] = 0(1-d) + V_{cc}(d)$$
$$ E[X] = d(V_{cc}) $$

![[duty-cycle-3.png | center]]
___
## Resolution
The **resolution** is the minimum incremental step (granularity) of the duty cycle. It is specified by the number of bits **R** (minimum step $\frac{1}{2^R}$).

**Example**
$R = 8$ bits, the minimum incremental step is $\frac{1}{256}$, so the duty cycles are:
$$ \frac{0}{256}, \frac{1}{256}, \frac{2}{256}, ..., \frac{255}{256}, \frac{256}{256}$$
___
## Switching Frequency
The **switching frequency** is the frequency of the PWM wave.
$$ f_{PWM} = \frac{1}{t_{PWM}}$$
___
# Basic PWM
A **basic PWM** design can be done as follows:

![[pwm-basic.png | center]]

The following module represent a `Basic N-Bits PWM`.

```verilog
module pwm_basic
	#(parameter resolution_bits=8)
	(
		input clk,
		input reset,
		input [resolution_bits-1:0] duty_cycle,
		output pwm_out
	);

	// Up counter
	reg [resolution_bits-1:0] Q_reg;
	reg [resolution_bits-1:0] Q_next;

	// Reset
	always@(posedge clk, posedge reset)
	begin
		if (reset)
			Q_reg <= 0;
		else
			// Refresh every clk
			Q_reg <= Q_next;
	end
	
	// Next state logic
	always@(*)
	begin
		// Counts up
		Q_next = Q_reg + 1;
	end
	
	// Output logic
	assign pwm_out = (Q_reg < duty_cycle);
	
	endmodule
```

The following testbench can be implemented to test the last module.

```verilog
// Timescale
`timescale 1ns/1ps

// Module
module pwm_basic_tb;
	localparam T = 10;
	localparam resolution_bits = 8;
	reg clk;
	reg reset;
	reg [resolution_bits-1:0] duty_cycle;
	wire pwm_out;
	
	// Instantiate the DUT
	pwm_basic_top #(.resolution_bits(resolution_bits))
	uut (
		.clk(clk),
		.reset(reset),
		.duty_cycle(duty_cycle),
		.pwm_out(pwm_out)
	);
	
	// Clock signal
	always
		begin
		clk = 1'b1;
		#(T/2);
		clk = 1'b0;
		#(T/2);
	end
	
	// Begin test
	initial
	begin
		// Reset for intial duty_cycle = 25%
		reset = 1;
		#2;
		reset = 0;
		duty_cycle = 0.25 * (2**resolution_bits);
		// duty_cycle = 50%
		repeat(2 * 2**resolution_bits) @(posedge clk);
		duty_cycle = 0.50 * (2**resolution_bits);
		// duty_cycle = 75%
		repeat(2 * 2**resolution_bits) @(posedge clk);
		duty_cycle = 0.75 * (2**resolution_bits);
		$finish;
	end
	
	// Prints results to console
	initial begin
		$monitor("time=%0t reset=%b duty_cycle=%d pwm_out=%d", $time,
		reset, duty_cycle, pwm_out);
	end
	
	// Dumps .vcd file
	initial begin
		`ifdef VCD_PATH
			$dumpfile(`VCD_PATH);
		`else
			$dumpfile("default.vcd");
		`endif
		$dumpvars(0, pwm_basic_tb);
	end

endmodule
```
With this design, there is the issue where `duty` can just take values between $0$ and $duty-1$ and the *pwm frecuency* is fixed by the `clk` signal.
