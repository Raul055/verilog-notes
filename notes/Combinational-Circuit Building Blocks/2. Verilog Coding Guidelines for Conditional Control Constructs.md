# Routing Networks
## Priority routing networks (`if-else`, `non`-parallel `case`)
A **priority routing network** is a combinational circuit that picks which signal to pass along based on a ranked list of conditions. If several conditions are true at once, the highest-priority one wins.

For example, based on the `4x1 Multiplexer if-else` module from [[1. Multiplexers]].

```verilog
always @(w0, w1, w2, w3, s)
	begin
		if (s == 2'b00) // highest priority
			f = w0;
		else if (s == 2'b01)
			f = w1;
		else if (s == 2'b10)
			f = w2;
		else if (s == 2'b11)
			f = w3;
		else
			f = 'bx; // lowest priority
	end
```
Look how the first condition (`s == 2'b00`) has the highest priority while `else` condition has the lowest. Verilog will output something like this:

## Multiplexing networks (parallel `case`).
A **multiplexing network** is a combinational circuit that selects one of several input signals and forwards it to a single output, based on a select signal.

For example, based on the `4x1 Multiplexer case` module from [[1. Multiplexers]].
```verilog
always @(w0, w1, w2, w3, s)
begin
	case(s)
		/* All are equal */
		2'b00: f = w0;
		2'b01: f = w1;
		2'b10: f = w2;
		2'b11: f = w3;
		default: f = 'bx;
	endcase
end
```
In here, all `s` inputs are equal and no priority exist; these can be seen as all inputs for a big multiplexer. Verilog will output something like this:

# Additional Guidelines
**In Combinational Circuits:**
- Output(s) is a function of current inputs.
- No storage elements (i.e. memory) should be included.
**In an always statement:**
- Variable(s) will keep its previous value if not assigned a new value.
- This means a latch might be inferred.

For example, look at the following module.
```verilog
module mux_4x1_nbit
	#(parameter N=3)
	(
		input [N-1:0] w0,l w1, w2, w3,
		input [1:0] s,
		output reg [N-1:0] f
	)
	
	always @(w0, w1, w2, w3, s)
	begin
		case(s)
			2'b00: f = w0;
			2'b01: f = w1;
			2'b11: f = w3;
		endcase
	end

endmodule
```
Here, observe the `default` and `w2` was omitted. Verilog will interpret it like the following:
![[add-guidelines.png | center]]

Observe how, because we omitted `w2`, it does not form part of the design. Additionally, a **latch** was inferred by verilog. Why is this? Revisiting the `always` block:

```verilog
always @(w0, w1, w2, w3, s)
	begin
		case(s)
			2'b00: f = w0;
			2'b01: f = w1;
			2'b11: f = w3;
		endcase
	end
```
Here, `w2` form part of the sensitivity list. Imagine `w2` was triggered, so, because it is in an `always` block and `f` was not assigned a new value, `f` will search for its previous value. This forms a *memory* which is **unwanted** and does not follow our combinational circuit guidelines.

# Avoiding Latches in Combinational Circuits
Some good practices to avoid latches in combinational circuits are:
- Make sure that all branches of the `if` and `case` statements are included (use `else` and `case`'s `default`).

```verilog
always @(w0, w1, w2, w3, s)
begin
	case(s)
		2'b00: f = w0;
		2'b01: f = w1;
		2'b10: f = w2;
		2'b11: f = w3;
		default: f = 'bx; // <-- this default
	endcase
end
```

```verilog
always @(w0, w1, w2, w3, s)
begin
	if (s == 2'b00)
		f = w0;
	else if (s == 2'b01)
		f = w1;
	else if (s == 2'b10)
		f = w2;
	else if (s == 2'b11)
		f = w3;
	else         //
		f = 'bx; // <-- this else
end
```

- Make sure the outputs are assigned in all branches (use default values).
```verilog
always @(w0, w1, w2, w3, s)
begin
	f = 'bx;
	m = 'b1;
	
	case(s)
		2'b00:
		begin
			f = w0;
			m = 'b0;
		end
		2'b01: f = w1;
		2'b11: d = w3;
		default: f = 'bx;
	endcase
end
```
